## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use

Def — присваивание значения переменной.
Use — использование её значения.

Номера строк соответствуют исходному коду с нумерацией
в файле docs/dfa_analysis.md.

| Переменная | Def | Use |
|---|---|---|
| log_entry | Строки 2 и 10 | Строка 13 |
| status | Строка 5 | Строки 10 и 15 |
| balance | Строка 6 | Строка 7 |
| new_balance | Строка 7 | Строка 8 |
| file | Строка 12 | Строка 13 |

Значение log_entry из строки 2 не используется:
в строке 10 оно заменяется новым.

### 1.2. Описание выявленных дефектов

**Дефект 1. Неинициализированная переменная.**

Переменная status получает значение только при amount > 0.
При amount <= 0 блок if пропускается, и в строке 10 возникает
ошибка UnboundLocalError.

Исправление: перед условием добавлено status = "pending".

**Дефект 2. Мёртвое присваивание.**

Начальное значение log_entry в строке 2 нигде не читается.
В строке 10 оно перезаписывается.

Исправление: ненужное первое присваивание удалено.

**Дефект 3. Утечка ресурса.**

Файл открывается в строке 12, но явное закрытие отсутствует.
Код не гарантирует своевременное освобождение ресурса.

Исправление: используется with open(...), который закрывает файл
при выходе из блока, в том числе при возникновении ошибки.

Полный анализ: [dfa_analysis.md](docs/dfa_analysis.md).

## 2. Дизассемблирование

### 2.1. Восстановленный код на Python

```python
def calculate_sum():
    total = 0
    counter = 1
    while counter <= 10:
        total += counter
        counter += 1
    return total
```

### 2.2. Пояснение логики

Ассемблерный фрагмент вычисляет сумму чисел от 1 до 10 включительно.

Ячейка -4(%rbp) хранит сумму, а -8(%rbp) — счётчик.
Их начальные значения равны 0 и 1.

Инструкция jmp передаёт управление проверке условия.
Инструкция cmpl сравнивает счётчик с числом 10.
Инструкция jle выполняет переход к телу цикла, если счётчик
меньше или равен 10.

В теле цикла значение счётчика прибавляется к сумме,
после чего счётчик увеличивается на 1.

После завершения цикла результат помещается в регистр eax.
Итоговая сумма равна 55.

Полный разбор: [disassembly_analysis.md](docs/disassembly_analysis.md).

## 3. Деобфускация

### 3.1. Расшифрованная строка

Следующий код приведён только для анализа, запускать его нельзя.

```text
import os; os.system('rm -rf /')
```

Для безопасного просмотра результата вместо exec(b)
используется print(b).

### 3.2. Анализ угрозы

Код пытается выполнить системную команду rm -rf /.

Команда rm удаляет файлы, параметр -r включает рекурсивное
удаление каталогов, -f отключает обычные запросы подтверждения.
Символ / обозначает корневой каталог файловой системы.

Возможные последствия — потеря данных и повреждение системы.
Фактический результат зависит от прав пользователя,
реализации rm и встроенных защит.

Base64 скрывает смысл команды при поверхностном просмотре.
Это кодирование, а не шифрование.
Функция exec выполняет декодированный текст как Python-код.

### 3.3. Методы защиты

1. Не выполнять неизвестные строки через exec и eval.
2. Проверять входные данные.
3. Декодировать подозрительные строки только для просмотра.
4. Ограничивать права запускаемых программ.
5. Использовать статический анализ безопасности, например Bandit.
6. Проверять вызовы системных команд.

Полный анализ: [deobfuscation.md](docs/deobfuscation.md).

## 4. Настройка и прохождение линтера

### 4.1. Настроенные правила

В корне репозитория создан файл .flake8:

```ini
[flake8]
max-line-length = 80
extend-ignore = E203, W503
exclude = .git,__pycache__,docs
```

Максимальная длина строки — 80 символов.
Проверки E203 и W503 отключены.
Каталоги .git, __pycache__ и docs исключены из проверки.

В файле .github/workflows/lint-check.yml настроен GitHub Actions.

Автоматическая проверка запускается при создании или обновлении
Pull Request, направленного в develop.
Используется Ubuntu и Python 3.10.
После установки flake8 выполняется команда flake8 .

Исправленная функция находится в src/fixed_transaction.py.

В ней:
- status получает начальное значение до условия;
- удалено мёртвое присваивание log_entry;
- файл закрывается через контекстный менеджер with;
- добавлены функции get_balance и update_balance.

В качестве учебной имитации базы данных используется словарь.
Ключ — идентификатор пользователя, значение — его баланс.

При исходном балансе 1000 и сумме операции 250 ожидаются
статус approved и новый баланс 750.

При amount <= 0 возвращается pending, баланс не изменяется.
