# Анализ потоков данных

## Исходный код

Для таблицы используется следующая нумерация строк. Пустые строки тоже учитываются.

```text
 1 | def process_transaction(user_id, amount, db_connection):
 2 |     log_entry = "Start processing"
 3 |
 4 |     if amount > 0:
 5 |         status = "approved"
 6 |         balance = get_balance(user_id)
 7 |         new_balance = balance - amount
 8 |         update_balance(user_id, new_balance)
 9 |
10 |     log_entry = "Transaction finished with status: " + status
11 |
12 |     file = open("audit_log.txt", "w")
13 |     file.write(log_entry)
14 |
15 |     return status
```

## Цепочки Def-Use

Def — строка, в которой переменная получает значение.
Use — строка, в которой значение переменной используется.

| Переменная | Def | Use |
|---|---|---|
| user_id | 1 — параметр функции | 6 — получение баланса; 8 — обновление баланса |
| amount | 1 — параметр функции | 4 — проверка суммы; 7 — вычисление нового баланса |
| db_connection | 1 — параметр функции | Не используется |
| log_entry | 2 — начальное сообщение; 10 — итоговое сообщение | 13 — запись итогового сообщения в файл |
| status | 5 — присваивание статуса approved | 10 — создание сообщения; 15 — возврат результата |
| balance | 6 — получение текущего баланса | 7 — вычисление нового баланса |
| new_balance | 7 — вычисление нового баланса | 8 — передача нового баланса в update_balance |
| file | 12 — открытие файла | 13 — запись сообщения |

Значение log_entry из строки 2 не достигает ни одного чтения:
в строке 10 оно перезаписывается.

## Выявленные дефекты

### 1. Использование неинициализированной переменной

Переменная status создаётся в строке 5 только при amount > 0.

Если amount <= 0, блок if пропускается. В строке 10 программа
попытается использовать status, хотя значение ей не присвоено.
Возникнет ошибка UnboundLocalError.

Исправление: присвоить status начальное значение до блока if.

### 2. Мёртвое присваивание

В строке 2 переменной log_entry присваивается "Start processing".

Это значение нигде не читается. При достижении строки 10 оно
заменяется итоговым сообщением.

Исправление: удалить первое присваивание или отдельно записывать
начальное сообщение в журнал.

### 3. Утечка ресурса

В строке 12 открывается файл. После записи в строке 13 отсутствует
явное закрытие файла.

Код не гарантирует своевременное освобождение ресурса,
особенно при возникновении исключения.

Исправление: использовать with open(...), чтобы файл закрывался
при выходе из блока, в том числе при ошибке.

## Дополнительные замечания

Параметр db_connection не используется.

Функции get_balance и update_balance в данном фрагменте
не определены. Для самостоятельной работы программы необходимо
добавить их определения или импортировать из другого модуля.
